# 제품 등록용 샘플 입력 데이터

현재 모터·베어링 모델에 맞춘 합성 데이터 50개 사례, 업로드 파일 80개입니다. 제조사 Demo Motion Works와 모든 DEMO 제품은 가상의 데이터입니다.

| 폴더 | 사례 | 용도 |
| --- | ---: | --- |
| 01_normal_motors | 20 | 정상 BLDC 모터, W/kW·g/kg 변환, 선택 질량 누락, 제품명 특수문자 |
| 02_normal_bearings | 10 | 정상 베어링, 내경·외경 |
| 03_edge_cases | 15 | 필수값 누락, 단위 오류, 음수, 내경·외경 비교, 0·소수, 한글 인코딩·서술형 |
| 04_multi_document | 5 | 문서 보완, 같은 값 병합, 필수값·선택값·제품명 충돌 |

파일 형식은 TXT 55개, XLSX 15개, PDF 10개입니다. PDF는 모두 텍스트가 포함된 2페이지 문서입니다. 숫자 사양은 2페이지에 있어 페이지 근거를 확인할 수 있습니다. XLSX는 Specifications 시트의 실제 숫자 셀과 별도 단위 셀을 사용합니다.

## 사용 방법

1. 처음에는 01_normal_motors/M001_bldcmotor.txt 또는 같은 이름의 PDF·XLSX 중 한 파일을 제품 등록 화면에 올립니다. 기대값은 전압 48 V, 출력 600 W, 속도 3000 rpm, 질량 0.75 kg입니다.
2. 일반 사례는 같은 ID의 형식 중 하나만 선택합니다. PDF·TXT·XLSX는 같은 제품 사양의 형식별 대안입니다.
3. 다중 문서 사례는 04_multi_document 아래 한 ID 폴더의 두 파일을 함께 올립니다. 서로 다른 사례를 한 작업에 전부 올리지 않습니다. 현재 등록 작업은 제품 하나를 대상으로 합니다.
4. 정상 베어링은 B001부터, 오류·수정 흐름은 E001부터 확인합니다. E013은 CP949 한글, E014는 UTF-8 BOM 한글입니다.
5. 등록한 제품을 온톨로지 탐색의 저장 제품 목록에서 선택해 정규화 값과 근거를 확인할 수 있습니다. 앱을 실제로 등록·실행하는 경우 기존 운영 DB 대신 별도 데이터 폴더를 사용하세요.

현재 기본 AGENT_MODE=mock에서는 파일을 저장하지만 추출 결과는 고정 Mock 데이터입니다. 업로드 내용을 실제 추출하려면 이미 구성된 LLM 설정과 AGENT_MODE=real이 필요합니다. 이 샘플을 만들거나 검증하는 동안 실제 모델은 호출하지 않았습니다.

## 기대 결과와 검증 범위

manifest.json은 업로드 목록, 원문 값·단위, 기대 정규화 값, 업로드 방식과 오류 유형을 담습니다. README·JSON은 참고 자료이며 업로드 대상이 아닙니다.

verification.json에는 각 파일의 SHA-256, 파싱 페이지와 각 업로드 조합의 실제 오프라인 검사 결과가 있습니다. 80개 파일을 앱의 DocumentService·ParserService로 읽었습니다. 원문에서 만든 고정 참조 응답으로 ExtractionAgent의 근거 검증·병합을 실행한 뒤, LLM 없는 OntologyAgent 규칙, 필수값·단위 검증과 SHACL을 검사했습니다. 75개 업로드 조합 모두 기대 결과와 일치했고, 정상 62개 조합은 정규화·SHACL을 통과했습니다. 오류 데이터가 의도한 오류를 드러내는 것도 확인했습니다. 관련 기존 테스트는 `89 passed in 7.27s`였습니다. 앱 코드 변경이 없어 전체 테스트는 이번 데이터 생성 작업에서 재실행하지 않았습니다.

이는 실제 LLM의 추출·분류 정확도 검증이 아닙니다. 특히 분류 규칙 오류는 LLM 분류 또는 수동 클래스 지정 결과와 달라질 수 있습니다. 실제 LLM 추출, 브라우저 업로드·등록 전체 흐름, 네이티브 Excel 동작은 미확인입니다. PDF 20페이지와 XLSX 15개 시트는 렌더링 이미지를 확인했습니다.

E008·E009의 내경/외경 관계는 일반 속성 검증에서는 통과하고 SHACL에서 실패합니다. 현재 Mock Validation 단계가 이 비교를 자동 수행한다고 가정하지 마세요. 온톨로지 탐색의 SHACL 검사에서 확인할 사례입니다. E011의 0 값은 현재 모델의 최소값 0 기준으로 허용되며, 실제 제조 제품의 적합성을 의미하지 않습니다. M007·M018의 선택 질량 누락은 경고를 허용한 정상 사례입니다.

D003의 필수 출력 충돌은 두 근거를 보존하고 출력 값을 미해결로 만들어 MISSING_REQUIRED 검증 대상으로 넘깁니다. D004의 선택 질량 충돌과 D005의 제품명 충돌은 DocumentConflictError로 중단됩니다. D002는 0.6 kW/600 W, 750 g/0.75 kg를 같은 값으로 병합하고 두 파일의 근거를 유지합니다.

정규화 기준은 출력 W, 질량 kg, 전압 V, 속도 rpm, 지름 mm입니다. mV·hp·rad/s·cm는 현재 해당 속성의 허용 단위가 아니므로 오류 사례에만 넣었습니다. 합성 수치는 원문과 기대값에 명시했으며 운영 모델·앱 코드·기존 DB를 변경하지 않았습니다.
